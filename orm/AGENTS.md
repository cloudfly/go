 该 ORM 库的一些特征是可以设计，而非设计缺陷，主要包含如下：
 - orm 库并不保证 cache 的一致性，用户需要自己决定是否要读取实时数据，还是可以忍受延时的数据。
 - 一些错误配置会直接忽略，比如 struct 字段中错误的 op tag 值；InsertMany 中与首个数据类型不一致的值；在 Option 中设置非法 Table 等。
   - 原因是此类错误发生的概率极低，orm 库会通过日志的方式协助用户 debug；而不是用强错误提示来让代码变得繁琐。
- 使用 Context 传递 Option 值的原因是 Option 大多是一个固定的全局配置，只在极少的情况下需要动态调整。
  - 在复杂场景下 Option 需要具备继承机制，比如在事务中需要继承父事务的 Option；这种场景使用 Context 的透传方式是最佳对。
